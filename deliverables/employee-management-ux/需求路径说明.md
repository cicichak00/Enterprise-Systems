# 员工管理 UX 草稿与需求路径说明

依据：20261014183642_rec_.mp4 录屏（约 59 秒）与现有员工管理页面。此稿用于评审交互与信息架构，不修改业务页面或真实员工数据。草稿中的数值仅作展示。

## 一、问题判断

1. 员工卡片「管理」以员工为起点；「批量操作」以功能为起点，两套路径先后顺序不同。相同的分成、结算、项目等配置被包装为不同入口，用户难以判断应从哪里开始。
2. 单员工权限浮层混合了员工权限、组长配置、员工及组员分成、项目管理。长表单与内部滚动掩盖了修改范围和保存影响。
3. 批量功能菜单为每项放置图标、标题和描述，多个项目占用大面积；勾选时员工卡片仍呈现任务和收益数据，选择目标不够聚焦。
4. 「管理」「权限管理」「批量操作」等名称过于宽泛，不能说明当前是查看数据、选择对象还是修改设置。

## 二、推荐方案：统一对象，按任务拆页

员工管理只保留一个列表。卡片「管理」改为「设置」，工具栏「批量操作」改为「批量设置」。两者共用设置分类、字段规则和提交逻辑，只改变目标员工的数量。

- 默认状态：保留员工身份、在职状态、结算方式、少量经营数据；设置按钮位于身份区。经营详情不混入设置。
- 多选状态：进入时不指定操作；自动收起经营数据，突出头像、昵称、ID、状态与复选框。整个身份行可选择，保留搜索与筛选。
- 设置首页：固定显示目标员工名称或人数，分为「收益与结算」「展示与工具」「权限与项目」。每行仅有名称、当前值或批量修改提示。
- 子设置页：每次只修改一项。分成采用明确数字输入，避免滑块难以精确控制；复杂项目权限采用独立页面。
- 组长权限：仅在真实角色为组长时显示专属分组；不向普通员工展示无关配置。批量时区分适用与不适用员工。
- 确认页：列出修改项目、目标范围与修改前后差异，再提交。长名单可展开，不连续叠加弹窗。

## 三、需求路径

### 单员工
员工管理列表 → 点击某员工「设置」→ 员工设置首页 → 选择配置项 → 编辑 → 预览差异 → 确认保存 → 返回列表并提示结果。

示例：用户1009 → 分成比例 → 输入 55% → 当前 51% 改为 55% → 确认。其他员工及其他配置不改变。

### 批量员工
员工管理列表 → 点击「批量设置」→ 勾选员工 → 点击「设置所选员工（N）」→ 同一设置首页 → 选择配置项 → 编辑 → 确认覆盖范围与差异 → 提交 → 展示成功及失败结果。

选择 1 人也允许继续，无需切换路径；选择 0 人时按钮禁用。修改一项后可以保留选择继续其他设置，点击取消才清空选择并退出多选。

### 项目权限
目标员工 → 项目权限 → 搜索或选择项目 → 只开启或关闭选中的项目 → 显示员工范围与项目范围 → 确认。不能把「未勾选项目」解释成关闭所有其他项目。

### 展示标签
目标员工 → 展示标签 → 输入或选择标签 → 预览姓名旁展示效果 → 确认。明确标签不等同真实角色，员工与组长的权限变更需使用独立角色规则。

### 组长专属配置
单员工设置 → 按真实角色出现组长专属区域 → 分别编辑组长分成、组员分成或查看权限 → 明确显示受影响人员 → 确认。批量混选不同角色时显示「适用 X 人 / 不适用 Y 人」，不能静默跳过。

## 四、浮层取舍与替代方案

推荐独立页适合分成、项目、钱包或组长等多字段配置：浏览、返回和保存范围清楚，不受半屏浮层高度限制。

紧凑浮层作为低成本过渡方案：先选员工，浮层仅展示 6 个简短操作入口，以两列布局降低高度；移除每项常驻解释，解释放入具体设置页。浮层标题显示目标人数，关闭返回原选择状态。浮层只承担选任务，不承担整套设置。

简单的线上/线下选择或开启/关闭可以使用轻量浮层，但复杂配置仍进入页面。禁止“功能菜单浮层 → 设置浮层 → 确认浮层”连续叠加。

## 五、关键交互约束

- 全选：默认全选当前已展示的结果，文案明确范围。若支持跨页全选，需单独说明总人数，不能把当前页全选变成全企业操作。
- 范围保持：已选 ID 保持稳定；改变筛选或搜索时显示隐藏的已选人数，提供已选名单查看。确认页列出最终目标，不凭当前列表重新推断。
- 批量当前值：配置不一致时显示「多种配置」，不自动以首人配置覆盖其他人；未编辑字段保持不变。
- 返回：设置首页返回多选列表时保留勾选；子页返回设置首页；有未提交编辑时提示保留或放弃，避免误丢失。
- 输入：分成限定合法范围与业务精度；不把空值解释为 0。展示标签的长度与字符规则以实际业务接口为准。
- 提交：防重复点击；提交中显示状态；失败保留输入。部分成功时显示成功/失败人数与原因，仅对失败对象重试。
- 适用条件：离职状态、角色、钱包能力或项目条件不满足时，提前说明原因并禁止不适用操作。
- 生效规则：历史订单、待结算收益及新任务是否受影响，须由业务确认后在确认页用准确文案说明；草稿不预设追溯规则。
- 权限：服务端再次校验操作者权限、目标员工归属与当前状态；前端禁用不能代替校验。

## 六、草稿评审与验收

草稿提供两个可点击方案：独立设置页（推荐）、紧凑操作浮层。可体验单人设置、多选、全选、修改分成、确认和返回。草稿只完整模拟分成及结算值更新，其余项用于验证路径与范围，不连接真实服务。项目稿仅选一个项目说明路径，正式实现应扩展到多项目及范围确认；组长条件、结果失败重试、跨页全选、未保存提示属于正式实现要求。

验收重点：
1. 单人与批量均先确定对象，再确定操作；没有再次选择员工的步骤。
2. 设置页始终可识别作用对象与操作项目。
3. 多选列表无完整经营数据干扰，0 人无法提交。
4. 配置首页不直接堆叠表单，复杂操作无需长浮层滚动。
5. 确认页准确显示目标、差异和覆盖影响，不改动未编辑字段。
6. 返回保留目标选择；提交失败可恢复；部分失败可单独重试。

建议优先顺序：统一入口文案与选择路径 → 多选收起数据 → 设置分类及子页 → 差异确认与结果反馈 → 组长适用逻辑与跨页选择。

## 七、2026-10-15 补充：进阶管理

上一版缺少真实身份与员工关联配置。本次以[进阶管理-身份与关联路径说明](进阶管理-身份与关联路径说明.md)为该部分最新要求：普通员工、小组长、组员均从单员工设置首页进入进阶管理；按身份呈现关联组员或所属小组长，并在确认页显示关联员工身份的联动变化。原文组长专属配置仅描述字段可见性，本补充明确包含普通员工升级、组员归属与解绑恢复流程。

## 八、项目配置更新

项目数量较多且按类型管理，本次用[项目权限-独立配置页说明](项目权限-独立配置页说明.md)替换原先单项目编辑的草稿：独立页按类型展示，支持跨类型多选与按变更保存，单人/多人共用，并避免以首位员工模板覆盖其他员工的未修改项目。
