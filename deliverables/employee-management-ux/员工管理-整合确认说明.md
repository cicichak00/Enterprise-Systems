# 员工管理 · 整合确认说明

本文件是本轮员工管理 UX 的统一评审入口；原需求路径说明、身份与关联说明、项目配置多版对照保留为历史参考。发生冲突时，以本文件和《员工管理-整合确认稿.html》为准。

交付范围：可点击原型和完整需求路径说明。未修改业务页面、未连接真实员工或权限接口，尚未部署上线。“确认稿”指集中评审稿，不代表全部业务细则已经确认。

## 一、本轮统一采用的 UX 方向

| 模块 | 合并后的方案 |
| --- | --- |
| 员工入口 | 一个员工列表；卡片“设置”处理个人；工具栏“批量设置”进入多选 |
| 单人/多人路径 | 先确定员工，再选择配置项，共用分类与设置规则，不重复选择员工 |
| 信息负担 | 多选自动收起经营数据；普通浏览可手动收起/展开数据；复杂配置进入独立页 |
| 进阶管理 | 从每名员工设置首页进入，包含普通员工、小组长、组员及对应关联 |
| 项目配置 | 采用已选定的“分组开关列表”，分类下直接展示项目开关，统一保存 |
| 分类展开 | 默认全部展开；分类可独立收起/展开；提供全部展开/全部收起 |
| 搜索与新增 | 搜索跨分类并自动展开命中项；新增项目进入所属分类，显示新增标识 |

不再将折叠分类作为必须的浏览步骤，不再使用左侧分类切换配合单项目下拉框。项目操作保持录屏中“开关 → 保存”的简单顺序。

## 二、统一页面与配置项

### 员工列表

搜索昵称或 ID；展示真实身份、展示标签、结算方式、用户 ID、所属小组长或组员人数。常规浏览可看少量经营数据，多选自动收起。标签是展示文字，不等于真实身份。

“设置”进入当前员工设置首页。“批量设置”只进入选择员工状态，不预先选择某一种设置。0 人时禁止继续；选择 1 人也可继续。全选范围为当前结果，已选人数在搜索后仍显示累计人数。返回保留选择；取消退出多选并清空选择。

### 设置首页

| 分类 | 设置项 |
| --- | --- |
| 身份与关联 | 进阶管理（单个员工） |
| 收益与结算 | 常规分成/进阶分成入口、结算方式 |
| 展示与工具 | 展示标签、快捷提词 |
| 权限与项目 | 项目权限、收益数据可见性、钱包权限 |

范围区显示员工名称/ID，批量显示人数和本次目标名单。进阶身份的分成入口回到进阶管理，不把常规分成与进阶分成混为一谈；批量混选进阶身份时常规分成入口不适用，需分别处理。

## 三、单人及批量的操作路径

**单人基础设置**：员工列表 → 该员工设置 → 选择配置项 → 编辑 → 预览差异 → 确认 → 返回列表及结果提示。

**批量基础设置**：批量设置 → 勾选员工 → 设置所选员工 → 选择配置项 → 编辑 → 逐员工预览当前值与目标值 → 确认 → 返回列表，保留选择继续设置。

**项目配置**：当前员工/所选员工 → 项目权限 → 调整项目或分类开关 → 保存配置 → 返回同一设置首页。项目采用直接保存，不额外增加通用差异确认页；当前范围和待保存数量始终明确。

**进阶管理**：某员工 → 进阶管理 → 选择身份 → 配置关联与分成 → 预览身份及关联人员变化 → 确认 → 列表双向更新。

## 四、三种身份及关联闭环

| 身份 | 关联 | 对应配置 |
| --- | --- | --- |
| 普通员工 | 无小组关联 | 常规分成 |
| 小组长 | 多名在职组员，可添加/解除 | 个人分成、业绩分成、查看名下组员数据权限 |
| 组员 | 唯一在职小组长，必选 | 组员个人分成，不高于所属小组长个人分成 |

- 小组长新增关联普通员工时，确认页同时展示该员工变为组员，以及所属小组长的变化；保存后双方列表同步更新。
- 本人、离职员工、其他小组长、已归属其他小组长的成员不可新增为组员，给出原因，不能静默抢占。
- 有组员的小组长先解除并保存全部关联，再恢复普通员工或切换组员。仅在未提交草稿中取消勾选不算完成解绑。
- 普通员工等价于不启用进阶管理；小组长/组员启用进阶规则。避免可保存“进阶开启但未选身份”的中间状态。
- 现有页面规则为新订单按进阶规则分佣、历史订单不变。展示标签调整不改变身份与权限。
- 多人设置暂不提供统一身份与关系修改；如需批量分配组员，应另设明确的小组长目标流程。

## 五、项目分组开关列表

### 浏览与折叠

独立项目页默认展示所有分类与项目，长列表向下滚动。分类标题显示项目总数、可用数、配置不同数、新增数及待保存数量。点击分类标题收起/展开，头部提供全部展开/全部收起。

折叠只影响显示，不更改权限、选择或未保存变更。搜索跨所有分类，自动展开命中的分类；搜索期间展示“搜索结果自动展开”，清空搜索后恢复之前的折叠状态。

### 单项与多项配置

单项直接调整右侧开关。分类“全部可用”支持全开/全关和半选状态；有搜索时改为“结果全开”，仅操作当前分类搜索命中项。选择某分类所有项目不代表授权未来新增项目。

多员工配置不同的项目明确显示“配置不同 · X/N 人可用”，不假装成已关闭；可统一开启，或使用分类操作统一配置。未修改的项目保持各员工原值，不能以首位员工模板覆盖所有人。

### 新增项目

接口按分类 ID 返回，新项目进入所属分类；标记新增且计数自动更新。新增项目的默认权限依据服务端实际规则，不因归类自动授权。新分类动态加入展示；原型固定六类、36 项只用于演示。

### 保存

按真正变化的员工—项目组合增量写入；恢复原值不计入待保存数。单员工和多人共用保存流程。有未保存修改时返回可继续配置或放弃。提交失败要保留草稿；部分成功只重试失败项目及员工，避免重复提交已成功部分。

## 六、需业务/接口确认的细则

这些内容不阻碍本轮布局确认，但不能从原型样例推断成真实业务规则：

1. 新项目默认可用还是禁用，以及“新增”标识的时间/已读窗口。
2. 关闭项目权限对进行中任务的影响，项目是否允许追溯历史任务。
3. 解绑后成员身份的服务端返回规则。本稿采用恢复普通员工；如业务不同，应一并修正确认文案与关系约束。
4. 现有组员是否允许直接转组，或必须先解绑再关联；必须遵守接口权限规则。
5. 批量与项目列表的分页全选范围；正式界面要明确“本页/已加载/全部匹配”，不能混用。
6. 钱包、收益数据及分成调整的接口权限、精度、结算生效时点与角色适用条件。
7. 多人身份关系及分佣更新的事务/版本校验，保证不会一侧成功一侧失败。

## 八、员工卡片最终展示要求

本轮取消自定义指标需求。移除自定义指标入口、选择/排序/预览配置页、收益/推广快捷切换及个人指标偏好读取。卡片使用固定六项：推广任务、累计回填、推广收益、员工收益、企业收益、分成比例，按三列两行展示。金额和数量下方显示今日新增，分成比例不显示新增。

卡片保留已确认的位置规则：用户 ID 在昵称后；在职状态、身份、展示标签和结算方式同一标签行；加入时间在标签下方；不显示“员工信息/更多信息”折叠区。保留角色关联摘要。仍可统一收起/展开数据，多选员工时自动隐藏指标。

其余单人、批量、身份关系与项目配置沿用前文。历史自定义指标页的方案不再作为当前需求或实现范围。
