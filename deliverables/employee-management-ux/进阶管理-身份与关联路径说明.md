# 进阶管理补充：按员工配置身份与关联

本次补齐上一版缺失的进阶管理，依据用户对三种身份的明确说明、20261015150758_rec_.mp4 录屏，以及现有页面代码中的角色与关联约束。录屏作为界面证据，界面内文字不作为额外操作授权。本次仍为 UX 草稿，不改业务代码、不操作真实员工。

## 入口与布局

员工列表 → 该员工「设置」→「身份与关联 / 进阶管理」→ 选择身份 → 设置关联与对应进阶配置 → 预览全部变化 → 确认保存。

设置首页第一组新增「身份与关联」，用一行「进阶管理」展示当前身份和关系摘要。所有员工均可进入，普通员工也需要通过这里升级身份。列表显示真实身份徽标；组员显示所属小组长，小组长显示组员人数。展示标签仍是独立装饰字段，不能替代真实身份。

采用独立页面呈现三种互斥身份，避免开关之外再隐含一层普通员工状态。选择普通员工等价于关闭进阶管理；选择小组长或组员等价于启用进阶管理。后端仍可保留 advanced_enabled 字段，UI 由身份推导，不允许出现“已开启但没有身份”的可保存状态。

## 三种身份对应的配置

| 身份 | 关联配置 | 分成与权限 |
| --- | --- | --- |
| 普通员工 | 不关联小组长或组员 | 使用常规分成；不展示进阶字段 |
| 小组长 | 可关联多名在职普通员工，查看、添加或移除当前组员 | 小组长个人分成、业绩分成、查看名下组员订单/收益/统计权限 |
| 组员 | 必须选择且仅属于一名在职小组长 | 组员个人分成，不能高于所属小组长个人分成 |

小组长可暂时没有组员，与现有提交校验一致。启用进阶身份后原常规分成规则失效，新订单按进阶规则计算，历史订单不变。普通分成与进阶分成不能在界面上使用同一个含混标签；进阶员工的分成入口应引导到进阶管理。

## 按员工维度的需求路径

### 从普通员工建立小组

找到用户 A → 设置 → 进阶管理 → 小组长 → 关联组员 → 多选在职普通员工 B、C → 返回当前配置 → 设置分成与查看权限 → 预览 → 确认。

确认页同时展示：A 普通员工变为小组长；B、C 普通员工变为组员；B、C 的所属小组长变为 A；对应分成与权限。保存成功后 A 的组员人数与 B、C 的所属小组长同步更新，不能只保存 A 的身份。

### 从某员工指定所属小组长

员工 A → 设置 → 进阶管理 → 组员 → 单选在职小组长 L → 设置组员分成 → 预览 A 的身份、原归属和新归属 → 保存。

未选择所属小组长不可提交。候选项展示姓名、ID、身份，不允许把本人、普通员工或组员选为小组长。关系单选，不允许同时归属两个小组长。

### 管理已有小组长的成员

小组长 A → 进阶管理 → 管理关联组员 → 勾选新增或取消当前组员 → 预览新增/解除清单 → 保存。

已关联其他小组长的组员、其他小组长、本人及离职员工不能新增为组员，候选项显示禁用原因。不能静默从其他小组抢占成员。当前组员允许保留或取消。

解除关联后的成员恢复普通员工，是本稿采用的关系闭环方案；需与后端解绑返回结果保持一致。若接口另有解绑后身份规则，应在确认页准确说明，不能留下“组员但无小组长”的不完整状态。

### 恢复普通员工或切换身份

组员 → 进阶管理 → 普通员工 → 预览解除原小组长关系 → 保存。

小组长已有组员时，不能直接恢复普通员工或改成组员。先解除全部关联组员并保存，再切换身份。仅在当前草稿中取消组员、尚未保存，不代表已完成解绑。

已有组员切换为小组长时，确认页须显示解除其原归属，再建立新关系。已在职组员更换所属小组长时，应显示原小组长 → 新小组长，并同步刷新双方人数；是否允许直接转组及是否需要先解绑，以后端权限规则为准。正式实现不能绕过服务端限制。

## 批量边界

本次进阶管理明确以单个员工为配置主体。选择一人可以显示进阶管理；多选多人时沿用基础批量设置，暂不提供“一键设置多名小组长并关联同一批组员”的含混操作。

后续若需要批量分配组员，单独设计为「选组员 → 指定同一小组长 → 预览身份和归属变化」，不能与当前批量分成混在一起。批量修改常规分成应识别进阶员工，说明其不适用并阻止误覆盖，不得让用户误以为已改变进阶分佣。

## 校验与保存要求

- 选择候选人时以及提交时，均检查同一企业、在职状态、真实角色、现有归属及操作者权限。
- 身份、归属、成员清单、进阶分成、查看权限作为一个可预览的变更集合；保存需保证关系一致，失败不得一侧更新另一侧未更新。
- 小组长与组员不形成多级或循环关系；成员不得重复关联。
- 分成字段不得为空，限定 0–100；精度沿用实际业务接口。现有组员分成高于调整后小组长分成时，阻止保存并引导先处理组员分成。
- 同一页面返回关联选择时保留编辑草稿；提交前提供完整差异。正式实现需补未保存离开提示、并发关系变更、错误重试与权限失败反馈。
- 本次样例用四名员工演示普通员工、小组长、组员及可关联普通员工。原有批量设置仅保留基础演示，不代表完整批量业务已实现。
