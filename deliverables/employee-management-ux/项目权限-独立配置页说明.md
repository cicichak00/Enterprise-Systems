# 项目配置：分类展开版（最新）

本稿替换“左侧分类导航 + 右侧项目复选框”的上一版布局。独立页内直接呈现“项目类型 → 类型下项目 → 项目可用状态”，新增项目归入对应类型。现有身份与关联配置保持可用，仅修改 UX 草稿。

## 页面结构与路径

员工设置 → 项目权限 → 查看分类摘要 → 展开分类 → 调整项目可用开关 → 预览变更 → 确认保存。

- 顶部明确员工姓名/ID 或批量员工人数，提供跨类型项目名称/ID 搜索和“批量设置”入口。
- 分类纵向排列，每类显示项目总数、可用数量、配置不同数量和新增数量；点击展开项目，支持同时展开多个分类。
- 每个项目显示名称、当前可用状态；普通编辑直接操作开关，不需要先勾选再选择可用/禁用。修改后标识“待保存”，确认保存后才真正生效。
- 批量编辑时显示选择框，支持选择单项、当前分类全部结果及跨分类多选，再统一设为可用或禁用。部分选中显示半选状态；完成多选清空勾选但保留已暂存变更。
- 页底默认只保留待保存数量与保存入口；批量编辑才展开所选数量及可用/禁用动作。
- 搜索跨全部分类，自动展开命中的分类；清空关键词恢复原展开状态。分类摘要仍统计整个分类，批量“选择本类搜索结果”只选择命中的项目。

## 后续新增项目

项目按接口返回的 type_id/category_id 自动进入对应分类，不依赖前端固定项目数组；分类计数由数据计算。出现新类型时新增分类分组；缺少类型的项目暂归“未分类”并提供明确维护路径。

分类标题显示新增数量，新增项目行显示“新增”，建议新项目优先排序。“新增”的时间窗口或已读规则需由业务确定；原型中两个固定标识只用于演示。

归入分类仅决定展示位置，不代表自动授予员工使用权限。新项目的默认权限沿用服务端实际规则，返回后明确显示可用/禁用；如希望未来同分类新项目自动继承权限，应另行定义“分类默认授权”规则和生效范围，不把一次全选现有项目当作永久授权。

## 保存与批量约束

- 单员工展示可用/禁用；多人现有权限不同时明确显示“配置不同”，提供“统一开启”，也可进入多选后统一禁用。不能把混合状态显示成已关闭。
- 只有明确操作且实际改变的项目进入确认页，按类型展示前后差异和实际受影响员工。未修改的其他类型/项目保持原样。
- 重复操作取最后一次目标权限；恢复原值不计变更。不能按首位员工配置模板覆盖其他员工全部项目。
- 有未保存修改时，返回提供继续配置或放弃的选择。
- 关联角色、项目归属和权限仍由服务端校验；提交需防重复，支持保留失败项重试和并发版本检查。

## 大数据量落地

原型按四类、每类六项演示，分类与项目名称取自既有产品上下文，非完整线上目录。

正式实现应分类懒加载、分页或加载更多，保持跨页选中 ID 和变更缓存。全选必须写明“本类已加载 X 项”或单独明确授权“全部匹配结果”，不能把局部选择变成全企业授权。移动端固定身份/搜索和底部保存区，适配安全区；列表通过页面滚动展示，避免半屏浮层套长列表。

项目下架、权限不足时保留原因提示；关闭权限对进行中任务和历史订单的影响须由业务确认。本稿不预设这些规则。
