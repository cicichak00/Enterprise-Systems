    <h2>员工离职确认弹窗</h2>
    <p class="req-summary">沿用现有“权限管理 → 员工权限 → 关闭管理权限 → 保存”入口，通过一个弹窗完成风险提示、协议阅读和离职确认，不新增多步页面。</p>
    <p><a href="employee-offboarding-simple-demo.html" target="_blank" rel="noopener">打开可交互弹窗 Demo →</a></p>
    <h3>单项需求范围</h3>
    <ol class="req-list">
      <li><b>触发方式</b><p>仅在员工由在职调整为离职并点击保存时弹出；开关关闭不立即生效。取消后返回表单，不提交离职。</p></li>
      <li><b>弹窗展示</b><p>显示员工昵称、协作 ID、待提现金额，显著说明企业关联解除、相关企业权限和后续业务分配停止，以及历史收益、结算责任和申诉权利保留。不得将本次确认表述为现实劳动关系已合法解除。</p></li>
      <li><b>协议与确认</b><p>提供《离职及企业关系解绑确认书》全文入口。操作授权及协议确认默认不勾选，全部勾选后启用确认按钮；协议返回后保留勾选状态。禁止以企业主单方确认代替员工放弃收益。</p></li>
      <li><b>结算分流</b><p>无余额或支持独立结算时可确认离职；结算异常或无法保障历史款项时提交审核，审核通过前维持原状态。不得因余额少而清零或自动回收至企业主。余额读取失败应阻止直接确认并支持重试。</p></li>
      <li><b>结果与留痕</b><p>防止重复提交；成功后刷新员工状态并通知员工，保留历史收益查询、结算及异议入口。失败不显示成功。记录操作人、员工、企业、时间、协议版本及结算快照。</p></li>
    </ol>
    <h3>验收标准</h3>
    <ul class="req-checks"><li>沿用现有表单和蓝色开关样式，通过弹窗确认，无新增多步流程。</li><li>身份、金额、关系切割及责任保留文案清晰，未勾选不可提交。</li><li>取消不改变员工在职状态；重复点击不产生重复操作；失败可重试。</li><li>有余额、零余额、结算异常及余额加载失败分别验证。</li><li>离职不清零、不自动回收员工已有款项；审核中不提前解绑。</li><li>员工通知、结算和申诉路径可用；320 / 375 / 414px 下弹窗可滚动且按钮可操作。</li></ul>
    <h3>交付路线与评审事项</h3><p class="req-hint">需求与 Demo 已整理 → 产品 / 法务评审 → 前后端实现 → 测试验收 → 上线核对。负责人、优先级、排期待定。正式开发前需确认历史收益独立结算能力、异常审核机制，并替换现有“离职余额回收至企业主”逻辑。当前发布为需求与演示，不表示业务功能已上线。</p>
