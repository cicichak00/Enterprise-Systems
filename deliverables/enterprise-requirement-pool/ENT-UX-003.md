<article class="req-detail" id="ENT-UX-003"><div class="req-meta"><span>ENT-UX-003</span><span>员工 / 企业主消息中心</span><span>2026-10-16 · 待评审</span></div><h2>员工消息中心与离职双向确认通知</h2><p class="req-summary">企业主发起离职后进入待确认，员工阅读风险并确认或拒绝。企业主收到待确认、确认、拒绝三类站内消息。本需求更新 ENT-UX-002：员工确认前不直接解绑。</p><p><a href="employee-message-confirm-demo.html" target="_blank" rel="noopener">查看双端消息中心与确认弹窗 Demo →</a></p><h3>需求与操作流程</h3><ol class="req-list"><li><b>企业主发起</b><p>保留关闭管理权限并保存的入口，通过弹窗发送申请。生成唯一申请编号，推送员工“离职待确认通知”，同时推送企业主“员工xx离职待确认”。待确认期间关系、权限保持不变，不回收余额。</p></li><li><b>员工消息中心</b><p>新增站内消息入口、未读数量及列表。通知详情展示发起企业、企业主、员工和时间，询问是否与该企业主解除当前企业关联。阅读不等于同意；暂不处理维持待确认，不设置默认同意或自动解绑。</p></li><li><b>风险告知与勾选</b><p>说明企业权限、后续任务、部分企业共享数据访问会因关系解除停止或变化，开发前列明具体受影响数据。历史余额、待结收益、合法查询及申诉权利保留，不清零、不自动转给企业主；必要结算和维权记录仍有查询或申请渠道。风险知悉与自愿解除默认不勾选，全选后才能确认。不捆绑放弃收益，不替代现实劳动关系解除手续。</p></li><li><b>确认并通知</b><p>员工确认后校验身份、申请编号和最新状态，执行解绑。企业主收到“员工xx已进行离职确认”；存在异常审核时应展示“员工已确认，解绑审核中”，不得误显示已离职。员工也收到回执，历史结算继续。</p></li><li><b>拒绝并通知</b><p>独立拒绝按钮无需勾选同意，二次确认并支持选填原因。企业主收到“员工xx已拒绝离职申请”，展示时间和原因；本次申请结束，关系不变。沟通后可重新发起新申请，旧记录保留。</p></li></ol><h3>验收及约束</h3><ul class="req-checks"><li>待确认、确认、拒绝均推送企业主；未读状态和业务状态分别保存。</li><li>同一企业和员工仅一条有效申请；重复提交、消息重试均去重。</li><li>服务端校验身份、编号、版本、最新状态；确认与拒绝原子更新，只允许一次成功。</li><li>旧消息只读，不允许操作另一条新申请；拒绝后重发使用新编号。</li><li>通知持久化、跨端可见、可靠投递及失败重试；记录操作时间、风险告知及协议版本。</li><li>只有关联员工和有权限的企业主可访问；覆盖加载失败、提交失败、通知失败及异常审核。</li><li>不因离职阻断员工历史结算与申诉；确认状态与解绑执行状态分开展示。</li></ul><h3>路线与待确认</h3><p class="req-hint">需求与 Demo 已整理 → 产品 / 法务评审 → 消息和关联状态接口 → 双端开发 → 测试 → 上线。负责人、优先级、排期待定，需补齐受影响数据清单及异常审核规则。Demo 仅为单页模拟，尚未接入真实站内消息与服务端。</p></article>
