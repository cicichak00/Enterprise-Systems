ENT-UX-003员工 / 企业主消息中心2026-10-16 · 待评审

员工消息中心与离职双向确认通知

站内信分类规则

  • 企业主与员工消息中心统一提供“系统”“平台”两个 Tab，默认展示系统。
  • 系统：员工加入、离职相关通知；离职待确认、主动确认、拒绝、超时确认均归入系统。
  • 平台：出单审核结果、订单结果；两端按同一规则分类，仅展示当前账号有权限接收的消息。
  • 切换分类仅筛选消息，不改变已读和申请状态；无消息时展示对应分类空态。倒计时仅在系统分类及离职详情展示。

24小时超时确认

2026-10-19 补充：计时从企业主成功提交离职申请的服务端时间开始，截止时间为提交时间 + 24小时。员工消息及风险弹窗显示一句动态提示：“请在 HH:MM:SS 内处理离职申请，逾期未操作将默认同意离职（超时确认）。”

  • 待确认 → 员工主动确认 / 员工拒绝 / 超时确认。超时确认不伪装为员工主动同意，双方消息、处理时间及操作来源须分别留痕。
  • 倒计时刷新、切换页面及暂不处理均不重置；每条新申请使用独立提交时间，拒绝或主动确认后停止计时。
  • 到期由服务端任务原子检查最新状态，只处理仍待确认的申请。员工确认、拒绝与超时竞争只能有一个最终结果，使用服务端时间。
  • 企业主收到“员工xx离职超时确认”；员工收到对应回执；若解绑异常，展示“超时确认，解绑处理中”，不能误报成功。
  • 企业主协议与员工风险提示均显著说明24小时默认同意规则；待法务评审，不以本原型证明该规则法律效力。
  • Demo 支持实时倒计时、刷新保留及“模拟24小时到期”，正式系统须保证关页、离线时服务端仍能执行。

三页 UX 结构

  • 01 企业主员工列表与权限管理：从对应员工进入权限管理，关闭管理权限 → 保存 → 阅读并勾选企业主协议 → 发送申请。关闭开关或取消均不直接生效。
  • 02 企业主消息中心：独立位置，仅查看待确认、已确认、已拒绝通知及详情，不放离职控制开关。
  • 03 员工消息中心：查看离职待确认消息，打开简洁风险弹窗，勾选确认或拒绝、暂不处理。

企业主发起离职后进入待确认，员工阅读风险并确认或拒绝。企业主收到待确认、确认、拒绝三类站内消息。本需求更新 ENT-UX-002：员工主动确认或24小时超时确认前不直接解绑。

需求与操作流程

  1. 企业主发起

    保留关闭管理权限并保存的入口，通过弹窗展示企业主离职协议全文入口、操作授权及责任确认；默认不勾选，全部勾选后才可发送申请。协议包含关联切割、历史结算、禁止恶意操作、员工意愿、平台责任边界及操作留痕。生成唯一申请编号，推送员工“离职待确认通知”，同时推送企业主“员工xx离职待确认”。待确认期间关系、权限保持不变，不回收余额。

  2. 员工消息中心

    新增站内消息入口、未读数量及列表。通知详情展示发起企业、企业主、员工和时间，询问是否与该企业主解除当前企业关联。阅读不等于同意；暂不处理在24小时期限内维持待确认；自企业主提交申请起24小时未确认或拒绝，则进入“超时确认”，按默认同意执行并通知双方。

  3. 风险告知与勾选

    说明企业权限、后续任务、部分企业共享数据访问会因关系解除停止或变化，开发前列明具体受影响数据。底层规则保留历史收益结算及合法查询、申诉渠道，不因弹窗简化而改变。员工弹窗仅展示精简的关系解除和企业关联数据风险告知、风险知悉及自愿解除勾选，支持确认、拒绝、暂不处理。移除重复询问句、余额权益说明、金额及劳动关系提示；上述结算责任等完整内容保留在企业主协议和平台规则中。勾选默认不选，全选后可确认。

  4. 确认并通知

    员工确认后校验身份、申请编号和最新状态，执行解绑。企业主收到“员工xx已进行离职确认”；存在异常审核时应展示“员工已确认，解绑审核中”，不得误显示已离职。员工也收到回执，历史结算继续。

  5. 拒绝并通知

    独立拒绝按钮无需勾选同意，二次确认并支持选填原因。企业主收到“员工xx已拒绝离职申请”，展示时间和原因；本次申请结束，关系不变。沟通后可重新发起新申请，旧记录保留。

验收及约束

  • 待确认、确认、拒绝均推送企业主；未读状态和业务状态分别保存。
  • 同一企业和员工仅一条有效申请；重复提交、消息重试均去重。
  • 服务端校验身份、编号、版本、最新状态；确认与拒绝原子更新，只允许一次成功。
  • 旧消息只读，不允许操作另一条新申请；拒绝后重发使用新编号。
  • 通知持久化、跨端可见、可靠投递及失败重试；记录操作时间、风险告知及协议版本。
  • 只有关联员工和有权限的企业主可访问；覆盖加载失败、提交失败、通知失败及异常审核。
  • 不因离职阻断员工历史结算与申诉；确认状态与解绑执行状态分开展示。

路线与待确认

需求与 Demo 已整理 → 产品 / 法务评审 → 消息和关联状态接口 → 双端开发 → 测试 → 上线。负责人、优先级、排期待定，需补齐受影响数据清单及异常审核规则。Demo 仅为单页模拟，尚未接入真实站内消息与服务端。

员工离职确认弹窗

单项需求范围

  1. 触发方式

    仅在员工由在职调整为离职并点击保存时弹出；开关关闭不立即生效。取消后返回表单，不提交离职。

  2. 弹窗展示

    显示员工昵称、协作 ID、待提现金额，显著说明企业关联解除、相关企业权限和后续业务分配停止，以及历史收益、结算责任和申诉权利保留。不得将本次确认表述为现实劳动关系已合法解除。

  3. 协议与确认

    提供《离职及企业关系解绑确认书》全文入口。操作授权及协议确认默认不勾选，全部勾选后启用确认按钮；协议返回后保留勾选状态。禁止以企业主单方确认代替员工放弃收益。

  4. 结算分流

    无余额或支持独立结算时可确认离职；结算异常或无法保障历史款项时提交审核，审核通过前维持原状态。不得因余额少而清零或自动回收至企业主。余额读取失败应阻止直接确认并支持重试。

  5. 结果与留痕

    防止重复提交；成功后刷新员工状态并通知员工，保留历史收益查询、结算及异议入口。失败不显示成功。记录操作人、员工、企业、时间、协议版本及结算快照。

验收标准

  • 沿用现有表单和蓝色开关样式，通过弹窗确认，无新增多步流程。
  • 身份、金额、关系切割及责任保留文案清晰，未勾选不可提交。
  • 取消不改变员工在职状态；重复点击不产生重复操作；失败可重试。
  • 有余额、零余额、结算异常及余额加载失败分别验证。
  • 离职不清零、不自动回收员工已有款项；审核中不提前解绑。
  • 员工通知、结算和申诉路径可用；320 / 375 / 414px 下弹窗可滚动且按钮可操作。

交付路线与评审事项

需求与 Demo 已整理 → 产品 / 法务评审 → 前后端实现 → 测试验收 → 上线核对。负责人、优先级、排期待定。正式开发前需确认历史收益独立结算能力、异常审核机制，并替换现有“离职余额回收至企业主”逻辑。当前发布为需求与演示，不表示业务功能已上线。

员工首页与“我的”页面信息调整

将身份与企业信息集中到“我的”，首页原位置承接 Banner，并按后台配置数量适配组件布局。

需求内容

  1. 顶部卡片迁移与整合

    首页原顶部卡片移至“我的”，与原个人卡片合并。保留用户头像、昵称、角色、手机号、用户 ID、企业头像、企业名称、简介和加入时间。重复字段只展示一次；缺失字段不展示“null”或“undefined”。站外登录入口保留在“我的”。

  2. 首页 Banner 区域

    在原卡片位置展示同尺寸 Banner，保留线上圆角、间距及页面顺序。支持多张轮播和指示点，单张不展示指示点。预览中的 Banner 文案为示意；实际素材和跳转目标由配置提供。

  3. 组件数量兼容

    按有效配置顺序展示 1–4 个组件。1 个通栏；2 个两列；3 个首项通栏、后两项并排；4 个两行两列。不留空白占位，长标题允许换行。第 4 项为布局示意，实际名称及入口由配置决定。

  4. 线上样式保真

    以提供的线上截图为基准，保留淡紫色卡片、按钮、字体层级、项目卡片和首页 / 收益台 / 我的导航。搜索、项目分类及任务操作沿用既有流程。
