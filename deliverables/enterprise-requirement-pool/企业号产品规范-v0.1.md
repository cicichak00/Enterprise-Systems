# 企业号产品规范 v0.1

整理日期：2026-10-29。性质：现有需求资料梳理稿，待产品确认；不代表服务端实现或上线状态。

## 统一规范
- 每项需求有唯一编号、目标角色、问题、范围、规则、验收标准、负责人、优先级、开发状态、依赖与证据链接。
- 状态统一为：待开发、开发中、待验收、已上线、废弃。所有状态在需求列表编辑；废纸篓可快捷恢复为待开发。已上线需有验收及发布依据，原型完成不能等同上线。
- 左侧菜单固定为需求列表、产品规则、需求展示、废纸篓。需求列表收录全部需求，注明版本和非必填的预计上线时间。
- 需求展示只展示开发中需求名称，点击进入基本规则及UX交互场景。页面固定“开发说明”按钮，点击右侧抽屉按前端、后端页签查看说明。
- 废纸篓收录状态为废弃的需求，仅保留历史、不进行开发；支持编辑内容及恢复待开发，恢复不代表批准实施。
- 负责人及排期无证据时标记待定，不推断开发百分比。需求变更记录日期、原因及替代关系。
- 页面统一表达操作对象、作用范围、当前值、变更值和结果；身份、展示标签、业务状态、消息已读状态分别记录。
- 保存需防重复；失败保留输入；批量部分失败明确成功和失败对象。权限校验由服务端执行。

| 身份关系 | 普通员工、小组长、组员互斥；组长可有多名组员，组员唯一组长；本人、离职、其他组长、他人组员禁选 | 关系保存需双向一致；有组员先解绑再变更身份 |
| 分成 | 常规分成只适用普通员工，0–100；进阶分成独立配置，组员不高于所属组长；新订单生效，历史订单不变 | 精度、时点、接口资格待确认 |
| 项目权限 | 分类可折叠，搜索展开命中项；混合值明确展示；只保存修改项，未修改保持原值 | 新项目默认权限、分页全选范围待确认 |
| 展示与工具 | 展示标签1–5字符且不改变角色；快捷提词默认关闭；收益可见性不改变实际收益 | 钱包细分能力不能推断为一个总开关 |
| 离职与通知 | 企业主发起，员工确认或拒绝；待确认不解绑、不回收余额；消息已读不等于同意 | ENT-UX-003更新002；均待评审，不能视为已实现 |
| 历史结算 | 离职保留历史收益、结算及异议路径；异常审核与解绑执行状态分开 | 现有回收逻辑需专项核对；具体能力待评审 |

## 需求备注
需求列表增加备注，记录异常、阻塞、依赖及其他情况说明，非必填。编辑保存后保留在需求记录中，导出包含备注；变更状态、废弃及恢复不清空备注。备注不自动改变需求状态。
