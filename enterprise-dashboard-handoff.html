业务与统计规则

身份与绑定关系

企业主必须先有右豹账号，由管理后台通过右豹用户 ID 加白后获得企业号企业主身份。
员工右豹用户通过企业主邀请码完成绑定后成为该企业员工。邀请码只是建立员工归属关系的路径，不构成第三种用户身份。
离职仅企业主可操作员工离职。生效后员工与企业主脱离归属关系，并立即失去该企业分发的项目及任务权限；离职前任务、订单和收益记录继续保留用于历史统计与对账。
员工关系勾稽期末在职员工 = 期初在职员工 + 周期新增绑定员工 − 周期离职员工；新增按绑定成功时间、离职按操作生效时间统计。

任务业务链路

  • 企业主将已关联且上线的项目分发给员工，员工获得项目权限后才能执行任务。
  • 漏斗为：当前在职员工 → 已分发项目员工 → 提交关键词员工 → 完成回填员工 → 产生有效订单员工，各阶段均按员工 ID 去重。
  • 离职员工不进入当前任务漏斗；离职前已发生的任务行为仍按业务发生时间保留在历史明细。
  • 关键词提交量和回填量均按成功提交记录数统计；失败、取消或已删除记录不计入。
  • 活跃员工指周期内至少成功提交一次关键词或回填的去重在职员工；活跃率分母为同期在职且拥有项目权限的员工。

订单分成与结算

分成比例企业主可为每名员工设置企业主/员工分成比例，比例在订单确认时形成快照，后续修改不追溯历史订单。
线下结算员工产生的整笔订单推广收益全部进入企业主账户，平台不拆分员工入账；线下如何结算不属于平台账务范围。
线上结算平台按订单快照中的分成比例，将同一订单拆为企业主收益一笔、员工收益一笔，分别进入双方账户。
有效订单仅统计审核通过且未退款、未作废的订单；发生退款或冲销时，按原订单结算方式和分成快照处理对应账户金额。

筛选与时间

  • 企业筛选控制整张看板；自定义时间按北京时间自然日统计。
  • 趋势与上一等长完整周期比较；当天未结束时对比昨日相同截止时刻。
  • 选择全部企业展示平台健康度及企业排行；选择单个企业后聚焦其员工、项目、订单和结算数据。

导出文件通用规则

  • 按当前企业、开始日期、结束日期筛选生成 Excel；文件名：企业号数据看板_企业名称_开始日期_结束日期.xlsx。
  • 每个模块独立工作表；所有工作表均包含企业 ID、企业名称、统计开始时间、统计结束时间、数据导出时间。
  • 金额字段统一为元并保留两位小数；比例字段导出百分比值；日期时间使用北京时间 YYYY-MM-DD HH:mm:ss。
  • 仅后台管理员可导出；手机号等敏感字段按权限脱敏，并记录导出人、导出时间和筛选条件。

开发对接说明

建议接口

看板汇总GET /enterprise/dashboard/summary?enterprise_id=&start_date=&end_date=，返回 owner_count、staff_count、active_staff_count、keyword_count、backfill_count、valid_order_count。
趋势数据GET /enterprise/dashboard/trends，返回新增加白企业主、新增绑定员工、活跃员工、关键词提交和回填序列。
员工关系GET /enterprise/dashboard/staff-relations，返回 opening_staff_count、new_bound_count、resigned_count、closing_staff_count、net_growth、resignation_rate。
任务漏斗GET /enterprise/dashboard/funnel，返回当前在职、已分发项目、关键词、回填、有效订单五阶段去重员工数。
收益结算GET /enterprise/dashboard/settlements，必须区分 offline_owner_amount、online_owner_amount、online_staff_amount，并返回订单分成快照。
导出任务POST /enterprise/dashboard/export，参数包含 enterprise_id、start_date、end_date、sheet_types；sheet_types 支持 enterprise_summary、staff_relation、task_funnel、project_usage、order_revenue、settlement_entry。异步返回任务 ID，完成后提供下载地址。

数据实现约束

  • 员工归属以邀请码成功绑定关系为准；企业主资格以右豹 ID 加白记录为准，禁止把邀请记录作为第三种用户身份。
  • 员工关系必须保存 bound_at、status、resigned_at、resigned_by；离职不得物理删除关系和历史业务数据。
  • 订单表必须保存 employee_id、settlement_mode、owner_ratio、staff_ratio 及分成规则快照，历史订单不得读取员工当前配置重新计算。
  • 线下结算：owner_credit＝promotion_revenue、staff_credit＝0；线上结算：两方入账金额之和必须等于 promotion_revenue。
  • 退款/冲销必须引用原订单结算快照，保证企业主与员工账务可追溯、可对账。

交互状态

  • 筛选后统一刷新所有卡片；请求期间展示骨架屏并禁用查询按钮。
  • 接口失败保留上一次成功数据；无数据时图表、指标、漏斗和表格分别展示空状态。
  • 明细入口携带 enterprise_id、start_date、end_date、settlement_mode；导出文件额外写入口径版本、导出人及导出时间。
